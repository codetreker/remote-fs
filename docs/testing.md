# 测试策略

本仓库怎么测：分层，以及那些让「全绿」有意义的规则。命令在根 [AGENTS.md](../AGENTS.md)；理由在对应的 Agent Note 里。

## 分层

- **单元** —— 核心逻辑：命名空间视图、缓存有效性、暂存、事件应用、定序。**不需要挂载点、不需要 `/dev/fuse`、不需要特权** —— 这些东西全都住在 `storage` 接口之上、`mount` 适配之下，一份内存实现就能驱动。偏重边界情况、错误路径、事件次序、并发交错，以及契约回归的永久用例。**一个关于缓存一致性的测试若需要挂载点，说明有个边界划错了。**
- **对拍** —— 把 `mount` 挂在本地目录实现上（不经网络），对挂载点与一个普通目录施加同一串操作，比较目录树、内容、错误码。不一致即缺陷 —— 不需要预先枚举「应该是什么样」。适合随机化操作序列，因为它不需要预期值。刻意的偏差必须是 `spec/` 里明确列出的非目标，按名字跳过并注明是哪一条。
- **故障注入** —— 一个实现 `storage` 接口、专门制造麻烦的包装层：延迟、响应与事件乱序、丢事件、续订时被告知无法重放、断线。它触及的是别处够不到的地方。
- **跨机器** —— 两个客户端进程 + 一个服务端，验证写入在一秒内可见、并发写后提交者失败、断线时报错。

对拍必须跑在**真正经过缓存与失效机器**的配置上。本地挂载若因缺少变更观察源而永远处于「已断裂」、什么都不缓存，验证的就是一个生产中不存在、且绕开了全部风险的路径。

## 覆盖率是必要的，从来不是充分的

它只证明那些行跑过了，不证明特性按交付的样子工作。

**未覆盖的行往往是死代码 —— 门禁正确地指出了该删的东西，而不是该补的测试。**

## 优先用真实实现，而不是 mock

只 mock 昂贵或不确定的边界：网络、时钟。下游全部保持真实。

一个手搓的替身只能证明桥梁在搬运字节，不能证明交付出去的那个东西按断言的方式工作。测缓存与失效时，用真实的 `mount` 加真实的本地 storage，只在网络那一层注入故障。

## 验证世界，而不是自述

一条端到端断言必须**从另一条路径**重新读取事实 —— 直接读底层目录、从第二个客户端读、重新执行命令。

**读我们自己的状态输出不算验证。** 这个系统会报告连接状态和未确认的写入；一个只断言状态输出的测试，恰恰放过了「状态输出说谎」这一类缺陷 —— 而那正是最需要被抓住的一类。

断言未被触碰的文件逐字节相同。

## 一个防护只有在回归真的能让它失败时才算防护

引入回归 → 看它变红 → 撤销。**没做过这一步的防护测试，等于没有。**

这条对反向判据（要求某种东西*不存在*）尤其重要：一个检查「代码里没有形同虚设的鉴权」的测试，若从未在真有一处形同虚设的鉴权时失败过，它证明不了任何事。

## 测真实入口

「真实入口」指交付出去的那个形态：真实挂载的挂载点、构建出的二进制、被第三方 import 的 package。

库内部直接调用能通过，而挂载后不行 —— 这类失败只有真实入口能暴露。作为库被链接的那条路径同样要测：不注册信号处理、不写标准输出、不调用进程退出。

## 每次改动必须带什么

**任何非平凡改动都要在同一次改动里新增或更新测试。** 判据与 Agent Note 相同。

- 改了行为 → 聚焦测试
- 改了跨包契约 → 契约两侧各有测试
- 修了缺陷 → 一个**在修复前会失败**的测试
- 改了错误路径 → 测那条错误路径

**错误路径不是可选覆盖。** 这个系统最重要的保证 —— 不可达即报错、不静默丢数据 —— 全都活在错误路径上；只测成功路径等于没测那些保证。

其中一条不能推迟：**断线状态下不得从缓存供应任何东西。** 它是「不知道真相时不得报告成功」的可执行形式。

## 挂载相关的测试是独立的一套

它们需要 `/dev/fuse`，且卸载在 CI 里容易不稳定。单元测试必须在任何地方都能跑 —— 那是它们真的会被跑的前提。

推送前只跑覆盖这次改动的检查，不跑全量；穷尽覆盖是 CI 的职责。**没跑过的检查不许说通过。**
