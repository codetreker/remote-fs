# 需求

系统最终要做到什么。本文是完整目标，不说什么时候做 —— 范围切分是带备选方案的决定，属于 `.agents/notes/`。

每条需求有编号，其它文档用编号引用它们。带 **【未决】** 的条目表示依据尚不充分，不得据此设计；解决它需要事实，不是讨论。

本文将服务端持有、可挂载或通过编程方式访问的逻辑文件树称为 **volume**。每个 volume 包含自己的根目录、节点、属性和内容。这里的 volume 是本系统的逻辑存储单元，不指宿主机磁盘分区或操作系统的进程／挂载命名空间。

## 一、文件系统语义

**R-FS-1** 文件系统入口呈现为一个普通目录树，支持读、写、创建、删除、列目录、建目录、删目录与改名。Linux 挂载还支持符号链接；Windows 入口的精确操作集合由 R-WIN-2 定义。

**R-FS-2** 未经修改的、为所在平台普通文件系统编写的程序能在文件系统入口上正常工作。「正常工作」的确切范围取决于 R-FS-3 和平台专有需求。

**R-FS-3【未决】** 需要兼容到哪一档工具链。
已知**不需要**：数据库、SQLite、共享内存映射的一致性。
未知：版本控制工具、编译器、包管理器是否会在 volume 内运行。
这一条决定了改名是否必须原子、文件大小与修改时间是否必须精确，从而决定了写入路径的形态。**在它被观测清楚之前，任何设计都不得选择一种事后无法满足这些性质的写入方式。**

**R-FS-4** 系统明确不提供：硬链接、跨客户端一致的共享内存映射、并发写者下的追加语义。文件的显式稳定占有与排他修改由 R-CC-3 及 R-CC-6 至 R-CC-11 定义。

**R-FS-5** 每个节点在其 volume 内有一个身份。文件系统入口向操作系统报告的文件身份必须稳定且不混淆节点；Linux 上表现为 inode 号，Windows 上表现为文件标识。同一个节点始终呈现为同一个身份，两个不同节点不能呈现为同一个身份，已经不存在的节点用过的身份不得再指向别的节点。

身份跟随节点走过改名，与它当时叫什么无关。**名字不能充当身份**：改名腾空的名字上创建出来的是另一个节点，把这两者当成同一个，内核就会把两个活着的节点当作一个——它按其中一个的长度去映射另一个，于是一个已经打开的文件描述符读到别的文件的字节，而映射了它的程序拿到 SIGBUS。

这一条在**变更由别的挂载点或别的客户端做出时同样成立**，而那正是它最容易失守的地方：一个挂载点只直接观测到自己执行的操作，别人做的改名不会经过它的任何一条路径。R-CON-3 被破坏时，破坏它的机制就是这一条不成立——旧的内容配上新的长度，正是「两者的混合」。

**R-FS-6** 成功打开的文件引用（Linux 文件描述符或 Windows 文件句柄）绑定到那个文件对象。后续读取、写入、截断与属性操作继续作用于同一对象；改名、删除名字或用另一文件替换该名字，都不得把已有引用转到替代物。失去最后一个名字后，有效的打开引用仍能访问原对象；操作不得因此重建旧名字或覆盖现在占据该名字的文件。

已有描述符读取的是该对象当前的内容与属性，不是打开时冻结的一份副本。一次读取的内容、大小与 EOF 判断必须来自相容的同一状态；多个读取调用可以观察到不同的已完成修改。引用失效或无法保持这一保证时明确失败，不能重新按原路径寻找替代对象。

**R-FS-7** 普通文件引用的写入和截断逐次同步生效，成功返回前由服务端确认结果，不等待关闭或后续刷新才提交。范围写只修改本次指定的字节范围，其余内容以同一对象的当前状态为准；缩短保留截点之前的内容，扩展部分读取为零。重叠修改可以依实际执行顺序各自成功，不隐含内容版本前置条件。失败或结果未知必须在相应调用中报告。

**R-FS-8** 依某个既有节点身份发起的打开或属性访问，必须确认操作仍针对该节点，不能因路径在查找后被替换而使用新节点。创建并打开时，存在性与排他创建判断、初始属性、截断及返回的对象必须属于同一次成功结果；不得先宣布成功，再补做决定该结果是否成立的步骤。

每个改变权威状态的操作都必须区分已完成、明确未执行与结果未知。调用方能够查询或安全重投同一个逻辑动作；重投不得重复产生效果，也不得因路径后来被替换而作用于另一个对象。传输取消不构成动作未发生的证明。这项规则适用于打开、关闭、内容与属性修改、改名、替换、删除及锁控制。

**R-FS-9** Windows 入口只对能按 Windows 名字规则无歧义表示的路径提供按名操作。同一目录存在大小写等价的多个名字、名字不是有效 UTF-8，或名字无法被 Windows 表示时，受影响的查找、目录枚举、改名与目录变更通知必须整体失败。不得挑选其中一个对象、遗漏条目、自动改名或修改 volume 来给出成功结果。

Windows 名字规则只约束该入口的解释及由它发起的命名修改。Linux 与编程入口保留自己的名字语义，不能因为同一 volume 被 Windows 访问而增加限制。只要已有引用与访问权限仍有效，不依赖名字观察的读写和属性操作继续作用于原对象；需要当前名字的操作不能使用打开时的旧路径猜测结果。

## 二、可见性与一致性

**R-CON-1** 一台机器上的写入或截断调用成功后，另一台机器上已挂载同一 volume 的进程必须在**一秒内**能观察到该修改；这不以关闭文件描述符为前提。仍打开同一文件对象的描述符同样适用 R-FS-6。

**R-CON-2** 已经连接的应用不需要轮询、刷新、重新打开文件或重新连接文件系统入口来取得 R-CON-1 的结果。观察方在修改确认一秒后发起的第一次相关文件操作必须得到权威状态；可见性不能要求应用反复请求直到偶然命中，也不能由系统内部固定周期的轮询或缓存到期来决定何时成立。

**R-CON-3** 一次修改在服务端提交完成前，对其它客户端不可见。一次读取观察到的是该修改之前或之后的完整内容状态，不拼接两者。多个已完成的写入调用各自形成可观察的修改，不把整个打开期间视作一次延迟提交。

**R-CON-4** 同一台机器上，写入方自己以及同机其它进程必须立即看到已写入的内容，包括文件大小与修改时间。

## 三、并发

**R-CC-1** 在调用方显式选择的内容版本校验工作流中，若提交所依据的内容版本已不是当前版本，**该提交必须失败**。普通文件引用写入不隐含这项前置条件，按实际执行顺序与写入范围生效；重叠写入可以各自成功。内容版本校验是独立目标，不能拿文件身份、advisory 锁或显式占有的 generation 代替内容依据。

**R-CC-2** 写不同文件必须完全互不干扰。

**R-CC-3** 调用方能够显式请求对一个文件的稳定占有或排他修改权限。这是强于标准 advisory 锁的独立扩展；R-CC-6 至 R-CC-11 的占有保证指这一扩展。多个稳定占有可以并存；稳定占有与排他修改互不相容，两个不同持有者的排他修改也互不相容。

稳定占有生效期间，文件的内容、存在性和节点身份保持不变。稳定权限本身不允许修改，持有者自己也不能只凭稳定权限改变文件。修改受保护的文件必须具有有效的排他权限；没有声明占有的调用方同样受这些保护约束。排他占有不构成普通读取的访问限制，读取继续遵守完整版本与错误行为的保证。占有约束授予之后的访问，与 R-CC-1 对旧内容依据的拒绝是不同的保证。

**R-CC-4【未决】** 显式内容版本校验工作流中的冲突，应由哪一个调用报告、调用方如何取得并处理这个结果。该未决项不要求普通文件描述符写入按旧内容依据失败。

**R-CC-5** 读一个正在被反复覆盖的文件**可以失败**。这类失败必须说的是「这一次没读到，再试可能就读到了」，且必须与「文件不存在」和「volume 的存储弄丢了它声称持有的字节」分得开——这三件事上层的处置完全不同。一次成功读取的范围必须来自该对象的一份完整内容状态，不能在一次读取中拼接不同状态；多个读取调用不承诺冻结同一版本。「读永远成功」不是需求。

**R-CC-6** 每次成功授予的占有都有明确、有限的保护期限。除持有者明确解除或期限届满外，系统不得提前撤销已经确认的保护；延长期限必须由明确的成功结果确认。调用方耗时较长、持续上传或暂时失联，都不能自行延长已经承诺的期限。

**R-CC-7** 对修改权限的判定与该修改作为同一个有序操作生效，不能被相冲突的占有变化插入。判定依据实际目标文件上的占有状态、持有者权限与有效期限；所有修改都遵守这一要求，包括没有声明占有的调用方。依赖某项占有权限、却在其到期或解除后仍未取得最终许可的修改必须被拒绝，即使没有任何其他持有者取得该文件的权限；较早阶段的检查不能代替最终判定。

在有效期内取得最终许可的修改可以稍后完成，但必须按已确定的顺序完成，然后相冲突的后继权限才能变得可用，新的权威状态观察也不能越过该顺序。已经取得旧视图的读取可以完成。上传和其他准备工作不构成最终许可，不能提前占住它来延长保护。

**R-CC-8** 服务端停止、异常退出或重启，不能使此前已确认且期限未满的保护失效。恢复服务必须保留这些保护，或在剩余承诺期限内提供等效的冲突阻止。无法证明已有保护仍被满足时，不得把占有状态当成空的并接受可能冲突的申请或修改。

**R-CC-9** 占有申请的等待必须有明确、有限的结束条件，等待中的申请与占有管理所需资源均受可配置上限约束。取消或超时不能自动被解释成「未曾授予」或「已经解除」；只有能证明动作未生效时才能如此报告，无法判定则明确报告结果未知。结束等待不得留下无期限的申请或资源占用。

**R-CC-10** 同一次占有管理动作的重复请求不得导致重复执行，不能因此产生第二份授予、重复延长保护，或改变该动作已经确定的执行结果；同一动作标识被用于不同内容时必须拒绝。查询可以报告等待中的申请后来获准、已授予的保护后来到期等状态变化，但须与原动作的执行结果区分。结果丢失后，调用方有办法核对该动作或安全地重复请求。

精确结果核对的承诺限于受理动作的授权方与对应持有者仍然有效、且处于其声明的有限历史保留期限内。有效控制活动延长核对期限时，新期限须明确告知调用方。授权方重启、被隔离，或对应持有者终止、到期后，旧动作必须明确报告已退役或结果未知；保留期限之外无法证明旧结果时，也必须明确失败。这些结果都不能被解释为未曾授予，也不能重新执行旧动作。精确动作历史不承诺跨越授权方重启，已经确认的剩余保护仍须满足 R-CC-8。

**R-CC-11** 占有绑定于文件的逻辑身份与明确的持有者，不随同名替换转移给另一个节点，也不因名字变化而转移给另一个持有者。一次修改只能使用调用方明确指定的保护范围，不能从路径相同、持有者相同或曾经取得过权限推导出额外授权。普通打开与读取不隐式取得稳定或排他权限，读取成功也不证明某项占有仍然有效。此项不承诺对子树或某个路径名字的固定占有。

**R-CC-12** Linux 挂载提供 `flock` 与传统 POSIX `fcntl` 记录锁：共享、排他、解锁、转换、阻塞和非阻塞获取，以及记录锁的冲突查询。它们是 advisory 锁，约束参与同一种锁协议的持有者；不参与的普通读写、改名与删除不会仅因这些锁被拒绝。普通打开不自动获取 advisory 锁或 R-CC-3 的强占有，三者不能互相冒充。

`flock` 约束整个文件，以 open file description 为持有者；`dup` 或 `fork` 继承的描述符共享该锁，独立打开是不同持有者。显式解锁或最后一个相关描述符关闭时解除。只读描述符也能取得排他 flock；转换模式先放弃旧锁，再尝试新模式，同模式重复获取不重复计数。

传统 POSIX 记录锁在同一挂载会话内以进程与文件为持有者，同进程线程共享，`fork` 不继承；关闭该进程指向同一文件的任一个描述符会解除它在该文件上的全部记录锁，不能波及其它文件或其它持有者。锁定字节范围可以超过当前 EOF，长度为零表示延伸到未来的文件尾；支持重叠范围替换、拆分、合并及部分解锁。读取锁要求可读访问，写入锁要求可写访问；转换失败保留原范围。冲突查询必须返回真实冲突，不能把未知说成未加锁。flock 与传统记录锁的冲突域分别独立。不同挂载会话中相同的 PID 数值不能被当作同一锁持有者。

**R-CC-13** advisory 阻塞申请在调用方及其会话仍有效时可以继续等待，不继承强占有申请的有限 Wait 语义；等待记录、锁范围与持有者仍受 R-INT-3 的资源上限约束。非阻塞冲突返回 Linux 兼容错误。取消与授予必须有可核对的结果，只有能够证明没有遗留授予时才返回可安全重试的 `EINTR`；结果未知返回 I/O 错误并隔离受影响持有者。

无法继续保证已取得 advisory 锁的连续性时，相关持有者的 I/O 持续报错，直到显式解锁或关闭，不自动重新获取后伪装为从未失去保护。锁继续跟随已打开的文件对象，不因改名、unlink 或同名替换转到新对象。强 S/X 的独立权限检查与期限、恢复保证继续成立。

**R-CC-14** Windows 入口按 Windows 文件访问规则提供读、写、删除的共享模式，以及共享、排他的字节范围锁。共享模式约束相冲突的打开与名字操作；字节范围锁约束相冲突的范围读取和写入。保护一旦生效，同一 volume 的其它 Windows 客户端、Linux 挂载和编程入口都必须遵守，不能通过更换入口绕过。

共享与范围保护绑定文件身份和实际持有者，不随改名、unlink 或同名替换转移。阻塞获取、立即失败、取消、精确解除和关闭各自必须产生可判定结果；结果未知时，受影响的持有者持续失败，不能假定锁未取得或已解除。Windows 共享模式、Windows 范围锁、Linux advisory 锁与 R-CC-3 的强 S/X 占有分别保留自己的语义，不能相互冒充。

## 四、故障行为与可观测性

**R-ERR-1** 服务端不可达时，操作以 I/O 错误失败。**不得**返回空目录、不得报告文件不存在、不得返回过期内容而不加说明。

**R-ERR-2** 无法判定的情况一律按错误处理。把未知归类为「不存在」会导致上层系统执行破坏性动作——重新生成、传播删除、覆盖写入——且不可恢复。

**R-ERR-3** 未能保存或无法确认保存的写入，必须在相应调用中明确报告失败或结果未知，不能先报成功再在关闭时丢弃。系统若持有已经由本地接口接受、尚未得到服务端确认的内容，不得静默丢弃，且必须能查出该状态；普通文件描述符写入遵守 R-FS-7 的同步确认规则。

**R-ERR-4** 运行中的系统必须能被查询：连接状态、是否处于任何降级模式、有无未能保存的写入。降级若不可见，等同于不存在。

**R-ERR-5** 客户端进程异常终止后，不得留下需要管理员权限才能清理的挂载或网络驱动器残留。

**R-ERR-6** 一个存储实现由多个可以各自失败的部分组成时，任何一部分不可达都按 R-ERR-1 失败。不得用尚能读到的那部分拼出一个看起来成功的回答——记着名字却读不到字节，与读不到名字一样，都是「不知道」。

**R-ERR-7** 随附的本地持久存储在打开时必须验证必要结构，并能证明各部分属于此前接受的同一个 volume。任何必要部分缺失、损坏、格式无法识别，或者来自另一份存储，都必须拒绝打开；不得初始化出一份替代的空 volume，也不得从仍可读取的部分拼出一份不完整的 volume。

**R-ERR-8** 随附的本地持久存储若无法把已保存的文件内容或 volume 状态验证为此前接受的那一份，受影响的读取或打开必须以 I/O 错误失败。不得把被改变、截断、来自另一份存储或属于另一个对象的字节作为合法内容返回。

## 五、集成与部署形态

**R-INT-1** Linux 客户端、Windows 客户端与服务端都必须是可被第三方程序独立链接的 package——它们会被集成进既有的 daemon service、桌面客户端与 server。集成方只选择自己需要的平台入口，不承担其它平台的依赖。

**R-INT-2** 作为 package，不得注册信号处理、不得写 stdout/stderr、不得调用进程退出、不得修改进程级设置、不得在包初始化时产生副作用。日志只能写入调用方给定的目的地。

**R-INT-3** 任何会累积的资源都必须有可配置的上限。运行在别人的进程里，无界增长是缺陷。一个 volume 耗尽自己的资源时，不能阻止另一个未耗尽 volume 的状态查询与停止；共享的进程级上限可以拒绝新的数据工作，但必须保留完成已接纳清理和报告真实状态所需的能力。

**R-INT-4** 提供独立二进制：服务端一个；daemon 与 CLI 合一，由参数选择以 daemon 方式运行。它们既是可部署形态，也是验证 package 的手段。

**R-INT-5** 提供不挂载的编程式访问方式，供无法挂载的环境使用。

**R-INT-6** 服务端背后的存储必须可替换。集成方接入自有存储是既定场景，因此他们必须履行的义务是契约的一部分，需要被明确写下来。

**R-INT-7** 身份认证由嵌入本系统的业务方负责，包括用户体系、凭据签发与验证，以及调用方身份的提供。本系统的操作授权必须可替换，由业务方针对 volume 与语义操作作决定，不内置用户、角色或 token 模型。长期运行的进程必须能在保持同一访问身份、不断开既有连接的前提下轮换凭据。

**R-INT-8** 客户端支持 Linux 与 Windows 11 24H2 及以上版本。Windows 上，未经修改的程序和系统文件管理器能够通过系统网络驱动器访问 volume，无需安装第三方文件系统驱动；普通用户能够在自己的登录会话内建立和移除映射，不要求管理员权限。Windows Server、Windows 11 24H2 之前的版本与其它客户端平台不在支持目标内。

平台专有的名字、属性、打开、锁、错误和生命周期语义由相应客户端入口负责。远端文件契约、存储实现和 volume 数据保持平台中立，不要求启用一种平台模式，也不理解某个平台的网络文件协议。平台差异不能缩减跨入口的对象身份、可见性、访问保护、授权和错误真实性。

**R-INT-9** 客户端与服务端之间的通信协议必须可替换，且需要支持 gRPC、WebSocket、SSE + REST 三种。集成方所处环境的网络与基础设施各不相同，通信方式不能是写死的一种。

**R-INT-10** 选用某一种通信方式的集成方，不应被迫承担其它几种带来的依赖。

**R-INT-11** 存储实现绝不能把两个不同的对象呈现为同一个对象。一个对象被删除之后，此前用来指代它的任何东西都不得转而指代另一个对象——要么指向不存在的东西，要么继续指向那个已经不在的对象。这是 R-INT-6 所说的、必须写下来的义务之一：上层无从校验它，一旦被违反，读到的是别人的字节，而没有任何迹象表明发生过这件事。

**R-INT-12** 存储实现可以依赖它自己的外部服务——对象存储、数据库。提供与运维这些服务是部署方的事，连接参数与凭据由部署方给定。这类依赖是集成方在选择该实现时一并承担的义务，因此每个实现必须说明它需要什么。

**R-INT-13** 独立服务端随附一种本地持久存储形态：一台 Linux 机器上的一个私有持久目录足以持有一个 volume，不需要外部对象存储服务，并在重新启动后继续满足正常挂载与跨机器可见性的保证。

## 六、volume 生命周期

**R-WS-1** volume 在服务端长期存在，与是否被挂载无关。

**R-WS-2** 挂载与卸载是频繁的日常操作，不是罕见的管理动作。

**R-WS-3** 一个长期未挂载的 volume 可以被重新挂载并正常使用。此时本地无任何既有状态。

**R-WS-4** 冷挂载后必须迅速可用——第一次列目录与最初几次读取不能慢到让人放弃。

**R-WS-5** 每个 volume 都有一个容量上限，上限的取值由部署方给定。系统必须把这个上限报告给挂载点上的程序——总量是多少、已经用掉多少、还能写多少，且这三个数必须是实测出来的——并拒绝任何会让 volume 越过上限的写入。「实测」指这三个数从持有该 volume 的存储里读出来，而不是从别处推算或估计；那个存储是去问底下的文件系统、还是去数自己那本随每次写入更新的账，是它自己的事。拒绝必须落在造成它的那次写入上，不能拖到关闭文件时才出现：大量程序从不检查关闭的返回值，那等于让那些字节无声地消失。拒绝要说的是「这个 volume 的额度用完了」，不是「机器上的盘满了」——后者是一句关于机器的话，而机器可能好得很。

**R-WS-6** 本地持久存储确认一次 volume 内修改成功之后，即使 server 随即停止、进程异常终止或机器失去供电，重新打开同一份存储也必须得到已经确认的名字、属性与内容。无法作出这项保证的修改不得被确认为成功。

**R-WS-7** 已无名字、但仍由有效打开引用持有的文件继续占用 volume 配额，其内容和属性保留到相关引用结束且已接纳的操作完成之后。释放或回收结果未知时不得提前宣告空间可用。重启可以使旧远端引用明确失效，但不得将它们按原路径重建，也不得清理另一仍有效拥有者的文件引用。

引用终止须先阻止该引用的后续发布，再排空已接纳的操作并回收内容；仅仅仍保留物理内容，不能授权已失效的引用继续写入。

已经接受的关闭时删除义务属于已接纳操作。它跨服务端停止、异常退出与重启保留，直到达到 R-WIN-7 定义的完成或明确未执行终态；旧引用失效不能把该义务遗忘或转移给同名替代物。

卸载以 `EBUSY` 失败时，仍在使用的挂载及其引用和锁保持有效；成功拆除挂载必须排空并释放其拥有的引用和锁，即使内核没有逐项发出 Release。关闭一次描述符时，某项清理错误不能使其它依法应执行的 owner 清理被跳过。

## 七、安全

**R-SEC-1** 本地文件系统入口默认只有创建它的用户可访问。放宽为其他本地用户可访问，等同于把持有者的凭据授予他们，必须是显式选择而非默认。

**R-SEC-2** 本地控制通道的访问权限等同于它所授予的能力，须据此保护。

**R-SEC-3** 落在本地磁盘上的文件内容仅所有者可读，且不得置于他人可预先占位的公共路径下。

**R-SEC-4** 凭据不得出现在日志、错误信息或状态输出中。

**R-SEC-5** 集成方启用操作授权时，每个服务端请求都必须按可信的目标 volume 与实际语义接受授权，包括打开的读、写、创建和截断意图，以及查询、续期与清理。拒绝或无法决定时，不执行本次请求的受控操作，不返回它请求的受控数据；已有引用或动作标识不能绕过检查。对本次请求的拒绝不能被解释为此前结果未知的动作未曾发生。

一个已授权并被 authority 接纳的多阶段动作可以自主完成其剩余固定效果，不把内部续作重新解释成新的外部请求；这包括 R-WIN-7 的删除义务。后来发起的状态查询、取消、补充清理或其它新动作仍须按其实际语义重新授权，权限撤销阻止这些新请求，但不抹去已接纳动作的结果与清理责任。

**R-SEC-6** 启用授权的持续输出必须在开始、重新订阅及每个有界发送单元（包括保活）前核对当前权限。权限变化阻止后续准入，已经准入的操作或发送单元可以完成；不承诺撤回已经交付的数据，也不承诺把外部权限变化与存储提交原子地绑定。业务方终止访问上下文后，相关持续输出必须能够停止，不能因对端不读取而无限占住输出与清理。

## 八、Windows 系统网络驱动器

**R-WIN-1** Windows 入口在本机把一个已授权的 volume 发布为当前登录会话可连接的系统网络驱动器；每个已发布驱动器只呈现一个 volume。发布、连接与移除由集成方显式控制，不在 package 初始化时发生，不要求安装驱动、取得管理员权限，或修改整台机器的缓存与安全策略。它不是面向局域网其它机器的文件服务器。

**R-WIN-2** Windows 入口支持以下可观察操作：

- 六种 create disposition：仅创建不存在目标，打开已存在目标，存在则打开／不存在则创建，仅截断已存在目标，存在则截断／不存在则创建，以及用新对象 supersede 已存在目标；
- 打开已有目录与 metadata-only 引用；
- 读取、范围写入、截断、刷新与关闭；
- 查询文件种类、大小、标识、支持的属性与时间，修改文件长度、支持的属性与可设置时间；
- 枚举目录，查询当前名字，改名、移动、同名替换、删除文件与空目录；
- 订阅目录名字、内容、大小和属性变化；
- 声明读／写／删除共享模式，取得、等待、取消与解除共享或排他的字节范围锁；
- 查询 volume 的容量、已用空间与可用空间。

每个操作都必须使用 Windows 能区分的成功、冲突、忙、权限拒绝、不支持、目标消失和 I/O 故障结果。未列入支持范围的信息类、控制操作或标志必须明确失败且不产生部分修改，不能返回零值或假成功。Windows 入口不承诺创建或遍历符号链接及其它 reparse point。

**R-WIN-3** Windows 入口遵守 R-FS-9 的名字规则。成功的目录枚举必须是同一次完整、有界观察：其中每个名字都能表示且彼此无歧义；无法完成时整个枚举失败。目录改名通知必须保留一次改名的旧名字与新名字关系。

通知历史不足或接收方跟不上时，必须明确进入 overflow 并重新取得权威目录状态。恢复期间不能从不完整状态回答成功；重取开始后的并发变化必须包含在重取结果中，或在恢复成功前随后交付。重取受 R-INT-3 的资源上限约束，无法完整恢复时明确失败，不能静默丢失变化后继续报告成功。

**R-WIN-4** Windows 报告的文件标识实现 R-FS-5：同一对象在重复打开和改名后保持同一标识，不同对象的标识不同。删除后重建同名文件、用另一文件替换该名字，或删除后在同一目录创建新对象，都必须产生不同标识。

替换前已经打开的句柄继续访问旧对象及其当前内容；替换后新打开的句柄访问新对象。旧句柄报告的标识不能随替换变成新对象的标识，新句柄也不能继承旧对象的标识。这个保证同样适用于目录和由其它 Windows、Linux 或编程入口发起的替换。

**R-WIN-5** Windows 入口支持可设置的 `READONLY`、`HIDDEN`、`SYSTEM` 与 `ARCHIVE` 属性。由 Windows 入口创建普通文件以及成功改变其内容或长度会设置 `ARCHIVE`，显式属性修改可以清除它；同一次写入不能先提交内容、再另行补设属性。其它入口的内容修改不自动解释或改变 Windows 专有属性。`READONLY` 按 Windows 文件操作语义拒绝由该入口发起的不相容内容修改与删除。`HIDDEN`、`SYSTEM` 与 `ARCHIVE` 不授予或撤销业务访问权。

`DIRECTORY` 与 `REPARSE_POINT` 只由节点种类决定，`NORMAL` 只表示没有其它可报告属性，三者不能被调用方独立设置。其它属性位的设置请求明确失败，不能静默忽略；Windows 专有属性不改变 Linux 或编程入口的名字、权限与授权语义。

新创建的节点必须具有已知的创建时间、最后访问时间、最后写入时间和变更时间。读取不自动改变最后访问时间；它只由显式的非零设置改变。内容或长度修改更新最后写入时间和变更时间，改名与受支持属性修改更新变更时间，创建时间不因这些操作改变。显式设置创建时间、最后访问时间或最后写入时间会把给定的非零值写入对应字段并更新变更时间；零值表示保持该字段不变。变更时间由系统维护，不能显式设置。

历史节点若从未记录创建时间或变更时间，Windows 查询对相应字段返回固定的零值，含义是“未知”。该零值不得被解释为真实的历史时刻，不得用当前时间、最后写入时间或其它推测替代，也不得因查询而写回。未知创建时间只在调用方显式设置非零创建时间后变为已知；未知变更时间在第一次会更新变更时间的成功操作后变为已知。已知时间不能恢复为未知。

**R-WIN-6** 每次 Windows 打开声明需要的读、写、删除访问以及允许其它持有者共享的对应集合。已有打开与新请求任一方向不相容时，新请求在产生文件或名字效果前失败。共享限制跟随文件身份，覆盖内容访问、截断、替换、改名与删除，并按 R-CC-14 约束其它入口。

共享声明由取得它的打开引用拥有；该引用关闭或所属会话终止并排空已接纳操作后才释放。每次授予与受它控制的操作在 authority 处形成明确顺序：排在授予之前且已接纳的操作可以完成，排在授予之后的冲突操作在产生效果前失败；较早的客户端预检不能替代最终排序。

字节范围锁支持共享与排他获取、立即失败或等待、取消及精确解除。每项锁由取得它的打开引用拥有，显式解除或该引用终止并排空已接纳范围 I/O 后释放。锁授予、解除与受控范围 I/O 遵守同一最终排序规则。一次包含多个范围动作的请求必须按 Windows 可观察的顺序报告已生效前缀与失败位置；冲突获取不得留下本应回滚的新锁，已经成功的解除不得因后续条目失败而恢复。结果未知时不能重复获取或解除一个猜测中的状态。

**R-WIN-7** 成功接受“关闭时删除”的打开，会建立一项绑定于原对象及其当时名字关联的删除义务。该义务在接受时已经通过本次删除授权；以后执行它是已授权动作的延续，不因原会话失效或权限随后撤销而重新解释。查询其状态仍须接受当前查询授权。

具有删除访问的有效句柄还可以显式设置或清除普通删除 disposition。设置为真时立即进入 delete-pending，并在同一次操作中验证当前对象、名字关联、共享模式、`READONLY` 与目录为空条件；任一条件不成立则无效果失败。任一具有所需删除访问且仍指向同一对象的有效句柄，都可以依据当前 pending 状态清除普通 disposition；该操作不能撤销任何句柄的关闭时删除义务，也不能作用于同名替代物。

发起句柄显式关闭，或其连接、会话、宿主进程终止时，义务进入 delete-pending。原名字关联被改名时，义务跟随同一个对象与关联；若该关联在触发前已被 unlink 或 replacement 分离，名字删除义务以明确未执行终止，旧对象只在最后引用结束后回收，绝不作用于后来占据该名字的对象。目录在触发时非空同样以明确未执行终止；有活跃关闭调用时由它报告结果，否则由可查询状态报告。

进入 delete-pending 后，相冲突的新打开和名字操作失败；已经允许删除共享的旧句柄继续按其既有权限访问对象，实际名字移除与对象回收等待 Windows 语义要求的最后一个相关句柄结束。清除一个句柄设置的普通删除状态，不能撤销另一个句柄已被接受的关闭时删除义务。

authority 从接受起拥有该义务，状态至少区分 armed、delete-pending、completed、明确未执行与清理失败。义务及其原对象／名字关联跨客户端崩溃、断线、停止、清理错误和 authority 重启保留。可重试失败继续由 authority 持有并暴露；只有名字已从原对象移除且对象回收责任已经确定，或明确未执行，才进入终态。

**R-WIN-8** Windows 自身的文件、属性、目录与负查找缓存必须服从 R-CON-1 至 R-CON-4。其它入口完成创建、写入、增长、截断、属性修改、改名、替换或删除后，Windows 中已经连接的进程在一秒内发起的第一次相关操作观察到权威结果；应用不需要轮询、刷新或重新连接驱动器。

远端状态不可达或无法确认时，缓存不能把旧字节、旧大小、旧属性、旧目录结果或先前的“不存在”作为当前成功结果返回。缓存失效、目录通知和重新观察必须共同保持 R-WIN-4 的对象身份：同名替换不能把旧句柄或旧标识重新绑定到新对象。

**R-WIN-9** 默认访问者必须是创建映射的同一个 Windows 用户和登录会话。其它本地用户、其它登录会话、匿名或 guest 身份均被拒绝；仅仅来自本机不能构成身份。入口必须认证该本地调用身份，并把每个请求绑定到已经认证的会话；连接和请求必须具有完整性保护，无法建立或维持保护时不执行文件操作，也不降级到较弱模式。

本地身份只决定谁能使用这条本机入口，不替代 R-INT-7 与 R-SEC-5 的远端身份和逐操作授权。凭据、会话密钥和可用于冒充身份的材料不得出现在日志、错误或状态输出中。

**R-WIN-10** 发布、驱动器连接、驱动器移除与停止分别有可观察的成功或失败结果。非强制移除遇到仍打开的文件或进行中的操作时必须以 busy 失败，原映射、句柄、锁和已接纳操作继续有效；不得删除一半后报告失败。若提供显式强制断开，它必须被标记为破坏性操作，且成功断开不表示在途 I/O 已成功或远端结果已知。

停止 Windows 入口时先进入 stopping 状态并永久拒绝新的发布、连接与文件工作，再排空已接纳操作，释放它拥有的映射、句柄和锁，并确认已接受的删除义务已经终结或由 authority 持续拥有。已释放的责任不重新取得，尚未完成的责任及其结果可查询；重复停止或以同一清理请求重试必须安全且不重复释放。stopping 不能恢复为运行状态，也不能接管新资源。

只有所有责任都已完成，停止才能报告成功并进入 stopped 终态。超时、结果未知或清理失败时返回错误，入口及调用方继续拥有这个 stopping 对象直至再次清理成功或显式转交给能够继续报告状态的拥有者；不能泄漏无主资源，也不能关闭调用方拥有的远端服务或存储。普通连接在远端 authority 重启后不透明恢复旧句柄、共享或范围锁；旧持有者明确失败，应用重新打开后取得新状态。

## 未列入需求的事项

以下曾被提及或容易被误认为需求，此处明确记录其状态，避免日后被当作既定目标：

- **离线读写与重放**：从未被提出为需求。当前立场是断线即失败（R-ERR-1）。
- **绕开本系统直接改动被服务出去的 volume**：不是被支持的用法。R-WS-5 的三个数字只覆盖经过本系统的修改，被旁路改动过之后它们不再准确，而此后任何经过本系统的流量都修不回来。
- **显式版本冲突的自动合并**：不是需求。R-CC-1 的版本校验工作流要求明确失败；普通范围修改仍按 R-FS-7 的实际顺序生效。
- **缓存跨进程重启存活**：不是需求，是可能的优化。
- **macOS、Windows Server 与 Windows 11 24H2 之前的版本**：不在客户端支持目标内（R-INT-8）。
- **局域网文件服务器**：Windows 能力只面向同机系统网络驱动器；不承诺让其它机器直接连接本机入口。
- **完整 NTFS 兼容**：不提供 alternate data streams、Windows ACL 编辑、hard link、稀疏／压缩／加密文件、reparse point 创建或遍历、共享内存映射一致性，以及 durable／persistent handle、multichannel 或透明故障转移。R-WIN-2 明确列出的操作仍必须完整满足。
- **离线缓存或断线继续工作**：Windows 入口同样遵守 R-ERR-1；不以旧内容、旧目录或延迟重放代替当前权威结果。
- **跨多个底层请求的大 I/O 整体原子性**：一次应用调用若被操作系统拆分，不额外承诺所有片段共享一个读取快照，也不承诺失败写入全量回滚。每个实际完成并报告的读取、写入与截断仍须满足 R-FS-6、R-FS-7、R-CON-3 与 R-ERR-3；实现和验收不得把单个片段的成功扩大成整个应用调用的保证。
- **改变系统全局缓存或安全设置**：不能以修改整机策略满足 R-WIN-8 或 R-WIN-9。
- **完整的 `F_OFD_*` 记录锁扩展**：不在 R-CC-12 对传统 POSIX 记录锁与 flock 的保证范围内。
