## Safe optimization boundaries

Repeated healthy schema construction is a strong source-backed opportunity. An [ordinary Store open](https://github.com/codetreker/remote-fs/blob/d394f2404c74c07245c3a80049518fdff8d31fb2/packages/metastore/sqlite/sqlite.go#L351) creates writer/read/snapshot pools and executes schema/volume validation. [OpenLocking](https://github.com/codetreker/remote-fs/blob/d394f2404c74c07245c3a80049518fdff8d31fb2/packages/metastore/sqlite/locking_store.go#L42) also acquires native ownership and inode-bound lease evidence, completes initialization, enables the authority and performs recovery. Most one-second matrix leaves do not intentionally sleep; they reconstruct this prerequisite before a small refusal or observation.

Ordinary physical schema may be shared while each child retains a fresh logical volume, connection lifetime, object namespace and checked Close. A parent healthy native owner may be borrowed only by a genuinely read-only matrix: each child keeps independent fault wrappers, counters, sessions, actions, references and workers; checked child cleanup precedes unchanged-state/health checks under the parent context. Internal pure validators may use independently rolled-back transactions with checked typed schema/data snapshots, PRAGMA restoration and zero pooled connections in use. Immutable ordinary database images require fully checked handle closure and complete WAL checkpoint before copying.

Native lease databases must not be copied onto new inodes. Lifecycle, uncertain commit, process death, evidence corruption, WAL recovery and synctest bubble ownership retain their own real transitions. Fresh native authority is explicit in the common lock contract. Read-only borrowing does not justify universal pooling, root-prefix facades, reduced workload, altered capability combinations, or swallowed cleanup errors.

The atomic storage case keeps 100 writes, two continuous readers, 128/96 KiB values and proof that both complete values were observed. Stress cases keep 4096 files/128 readers; share admission keeps all 144 semantic vectors; bounded payload, history, crash, migration and backend variants retain their original sizes and assertions. Race, `-count=1`, watchdogs, strict no-skip/verdict checks and package-local coverage remain acceptance conditions. Optimizations below identify removable preparation, not permission to weaken those conditions.

## Priorities and reversible deferrals

The immediate case-only candidates are healthy ordinary schema sharing, read-only native parent preparation, the existing checked transaction fixtures, historical healthy-seed transaction batching, and large-directory fixture allocations that never appear on the wire. These remove prerequisite work while keeping the same production entrypoints and independent child ownership. The localstore checkpoint-worker test also has two explicit two-second retry intervals; filesystem barriers already hold the failure and recovery states, so a shorter test retry interval can preserve the observations.

The SMB share matrix executes 480 unconditional session Renew calls, 240 per transport. Its original five-minute lease/history exceeds the observed 44.23/51.41-second transport children. A test fixture can retain conservative lease/history deadlines anchored before each status/renew request and omit a redundant Renew only while both bounds cover the next operation's allowed interval. Near either bound it must still perform a real Renew and accept the current native action epoch. This is a source opportunity, not a measured share of the 95.63-second root. All 144 vectors, native/non-SMB directions, CREATE/Open/Close operations and 336 object checks remain necessary.

The HTTP binary already takes 9.4365 minutes and runs on its own runner; root SQLite takes 9.1382 minutes. Their opportunities matter to the aggregate required gate, but do not directly subtract time from Contract and unit tests. Mounted-only opportunities likewise affect the mounted job. Read-only HTTP/FUSE matrices can be optimized locally later with fresh handlers, references and cleanup checks. Deferral costs a later package-local fixture change; no new shared global fixture should make that change require replacing the test architecture.

Fresh native lock contracts, localstore's permanently bound physical root, SIGKILL/WAL/evidence-recovery cases, synctest driver ownership and atomic/stress workloads remain the expensive paths described in the inventory. General native pooling or copying a bound database would cross identity/lifecycle conditions; an explicit independent-factory experiment would need its own full-suite measurement and isolation proofs. Production SQL/JSON/publication changes require profiling and error-path validation. Deferring them retains current behavior and costs a separately scoped implementation, rather than burying a production change inside case preparation.

## What would establish the ten-minute result

A matched before/after comparison must pin toolchain, race settings, process limit, emulator and workload; compilation warmup is reported separately. Selected-root sums establish local preparation gains, not CI wall time. Every existing named verdict must remain, no skip/fail or missing verdict is acceptable, and each package's own coverage blocks must be compared. Borrowing preparation adds obligations to prove successor health, native capability preservation, complete cleanup and unchanged shared state.

The final evidence for the budget is a complete hosted Contract and unit tests step under ten minutes on the delivered head, with the original watchdogs, strict wrapper and coverage policy. Whole-run and sibling-job timings must be reported separately. A single hosted before/after result is observational because runner load and contention vary; an under-ten-minute observation does not establish a worst-case guarantee. No candidate assessment or fixed-duration scheduling projection in this frozen report claims that outcome.
