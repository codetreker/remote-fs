# Agent Note: 缩短文件释放的配额只能在提交成功后借出

Status: proposed

## 问题

严重级别：P1。[R-WS-5](../../../../docs/spec/requirements.md) 要求拒绝会超出 workspace 上限的写入。[limited.Write 在调用底层 Write 前就 reserve 负增量](https://github.com/codetreker/remote-fs/blob/252259f1b89682a5b2acf54004f0fe8b8677528d/packages/storage/limited/limited.go#L513-L541)，使尚未提交的缩短提前增加其它写者可用的额度。缩短失败后的回滚不能撤销已经成功的另一笔写入。

在该提交上，以 localdir 包装一个可阻塞并失败的 `Write`，配额设为 4096 字节，初始 `a` 占满 4096 字节。通过 limited 将 `a` 缩短为零，在底层写入前阻塞；随后写入 4096 字节的 `b`，再放行 `a` 并使其返回 `EIO`。`b` 成功，`a` 保留原内容，实际用量达到 8192 字节。

## 提案

让增长预留与缩短释放分别服从提交时序：增长在提交前占用额度，缩短仅在底层确认成功后释放，失败保留原用量。计数与并发写者的可用额度必须来自同一套结算规则。

本项补足[容量上限](../../implemented/architecture/2026-08-21-space-limit.md)的失败回滚；[目录改名导致采样失效](2026-09-07-keep-quota-accounting-stable-across-directory-renames.md)单独处理。

## 备选方案

未比较具体实现方案。全 workspace 写入串行化会让一个慢写者阻塞无关文件，修复必须保留 R-CC-2 所要求的不同文件写入独立性。

## 验收标准

- 重现上述失败缩短时，`b` 的 4096 字节写入以 `EDQUOT` 拒绝，`a` 仍为 4096 字节；`Space.Used` 与底层实测均为 4096。
- 阻塞中的缩短不能增加可用额度；成功缩短后只释放一次，并使随后独立写入获得相应额度。
- 覆盖取消、底层失败、等长写入、增长预留失败与超额 workspace 的缩短；失败保持原错误，所有完成调用后的统计与底层内容一致。

## 风险

延后的是配额上限保证，失败缩短可能让已成功提交的内容超过配置上限。修复会让等待提交的缩短暂不提供可用额度，这是底层仍持有那些字节的实际状态；不能靠事后重算或删除另一写者的成功结果纠正超额。
