# Agent Note: 缓冲读取必须使用同一版本的长度

Status: proposed

## 问题

严重级别：P1。[R-CON-3、R-CC-5](../../../../docs/spec/requirements.md) 要求并发覆写下的读取成功时得到完整的某次提交。FUSE 句柄保存打开时的内容，而 [handle.describe 仅在节点身份变化时覆盖干净句柄的长度](https://github.com/codetreker/remote-fs/blob/252259f1b89682a5b2acf54004f0fe8b8677528d/packages/fuse/handle.go#L236-L249)。普通覆写可能保留身份，新的长度于是与旧缓冲区同时生效。

在该提交上，以 SQLite metastore 与 memory object store 挂载文件系统：写入 65536 字节的 `A` 后打开读句柄；通过 storage 覆写为 `BBB`，确认覆写前后的节点 ID 相同；对旧句柄执行 `Stat` 再读至 EOF。`Stat` 报告长度 3，读取成功返回 `AAA`，既非完整旧内容，也非完整新内容。

## 提案

在句柄读取与属性呈现之间保持内容版本和长度一致，覆盖身份保持与身份改变两类覆写。修复必须同时维持路径 `stat` 对当前命名空间的描述，避免某个旧句柄让同机其它程序一直看到旧长度。

本项补足[节点身份决定](../../implemented/bug-fix/2026-09-01-a-name-is-not-an-identity.md)未覆盖的普通覆写；[跨句柄页缓存](2026-09-07-prevent-cross-handle-page-cache-staleness.md)仍有独立的触发条件和验收。[打开文件的身份钉住](../architecture/2026-08-20-nothing-pins-an-open-file.md)继续拥有按旧路径提交可能写到另一节点的写入问题。

## 备选方案

未比较具体实现方案。节点身份只能区分节点，不能代替内容版本；修复不能要求所有后端每次覆写都更换身份。

## 验收标准

- 上述 65536 字节 `A` 覆写成 `BBB` 的顺序下，旧句柄读至 EOF 成功时只能得到完整旧内容或完整新内容；允许符合 R-CC-5 的显式读取失败，禁止成功返回 `AAA`。
- 覆盖变长、变短、等长、身份保持和身份改变；用于裁定 EOF 的长度必须对应实际交付的内容。
- 保持旧句柄打开期间，路径 `stat` 与新句柄仍能观察到当前已提交内容的长度，不能被旧缓冲区长期覆盖。

## 风险

延后的是整文件版本完整性保证，读者可能把截短的旧字节当作有效文件继续处理。go-fuse 可能在未指定句柄的属性请求中选取已有句柄，因此仅把所有 `Getattr` 改为读取缓冲区长度会引入路径属性陈旧；修复须共同检查节点属性、句柄属性与内核 EOF 行为。
