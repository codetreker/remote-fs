# Agent Note: 严格测试检查保留实际执行的覆盖率文件

Status: proposed

## 问题

[严格测试脚本](https://github.com/codetreker/remote-fs/blob/134e936ce3bde78a9db7becdfbccd72d6efe7536/.github/scripts/assert-every-test-ran.sh#L35-L41)先执行 `go test -json`，再以相同参数执行 `go test -json -list '.*'`，用二进制中的测试清单检查遗漏。调用方显式传入的 `-coverprofile` 因而也进入第二次调用；列举不执行测试，却覆盖同一路径中的真实 profile。

已执行用例曾报告 86.1% 覆盖率，脚本结束后 profile 却只剩一行 mode 头，函数报告也没有实际函数记录。测试是否执行的门禁仍可通过，但留下的文件无法证明哪些语句运行过，违背[测试策略](../../../../docs/testing.md#覆盖率是必要的从来不是充分的)对覆盖证据的使用前提。

可重现的条件是：对含有实际执行语句的测试包，通过脚本传入 `-count=1` 与显式 `-coverprofile`；检查最终文件是否仍有覆盖块及非零执行计数。不能仅凭测试日志中的百分比认定输出文件有效。

## 提案

保留第一次实际测试执行产生的 profile，使后续测试清单检查不能覆盖它。处理 Go 支持的显式参数写法、GOFLAGS 中的 profile 设置及其覆盖次序，保持其它测试参数与错误结果的含义。

范围仅为覆盖文件的归属与保留。skip、无匹配测试、已编译测试未给出 verdict，以及测试或清单命令自身失败，都继续使脚本失败；不改写 Makefile、CI 分工或测试清单的来源。

## 备选方案

**清单调用过滤输出 profile 的参数。** 让列举保持只提供测试清单，但必须同时处理显式参数和 GOFLAGS，不能遗漏一种写法后仍覆盖文件。

**保存并恢复实际执行的 profile。** 可以保留清单命令的参数形状，代价是额外的文件读写与清理；保存或恢复失败也必须显式失败。两者尚未选定为永久实现。

## 验收标准

- 用已知函数与执行路径的小型包调用脚本，最终 profile 除 mode 头外含真实覆盖块，至少一项执行计数大于零；`go tool cover -func` 列出的真实函数数与该包一致，覆盖结果与实际执行一致。
- 覆盖 `-coverprofile=PATH`、`-coverprofile PATH` 及 Go 支持的 GOFLAGS 设置与显式覆盖；最终保留的是执行测试的文件，不是列举产生的文件。
- 注入 skip、空测试集合、缺失 verdict、测试失败和列举失败，原有门禁全部仍返回失败；未请求 profile 的普通调用保持原行为。

## 风险

延后期间，脚本成功与日志里的覆盖率都不能证明最终 profile 可用。参数过滤不完整会继续丢失证据；恢复文件时漏报 I/O 错误可能留下错误的产物。修复不能以取消清单检查或放宽严格测试门禁换取有效 profile。
