# Agent Note: CI 为整包 race 测试保留有界执行预算

Status: implemented

## 问题

CI 的 contract / unit 步骤给每个测试二进制五分钟总预算，所属 checks 作业有十分钟上限。[272754a 的运行](https://github.com/codetreker/remote-fs/actions/runs/34150190141/job/101830665461)在 SQLite 包累计 300.026 秒时触发 watchdog；当时正在运行的子用例才开始约 216 毫秒，栈在 SQLite 查询路径上处于 runnable 状态。这个时刻不能证明该子用例卡死。

SQLite、metastore 契约测试及 Go 依赖未变的两次先前运行，包耗时分别为 [250.096 秒](https://github.com/codetreker/remote-fs/actions/runs/34147842445)和 [239.588 秒](https://github.com/codetreker/remote-fs/actions/runs/34148464671)。三次均完成的 225 个顶层用例，报告时长之和较后一次基线增加 76.26 秒；其中基线至少 0.1 秒的 183 项，中位倍率为 1.42，146 项更慢。五分钟上限只比成功基线多约 50 至 60 秒。

这些数据支持整包累计执行余量不足，没有确定基础设施原因，也不能排除间歇性回归。被 watchdog 截断的其余测试没有通过结论。

## 决定

[CI workflow](../../../../.github/workflows/ci.yml)中，checks 作业总上限为二十分钟，contract / unit 步骤的 `go test -timeout` 为十分钟。后者约束每个包测试二进制的累计执行，不是单个操作的允许延迟。

race、`-count=1`、严格 verdict 检查与包划分保持原义。单项 deadline、副本可见性验收的三分钟进程预算与一秒可见性断言、覆盖率门禁及受保护的交付检查均不放宽。预算与判据的分工见[测试策略](../../../../docs/testing.md#ci-执行预算)。

## 备选方案

**保留五分钟／十分钟。** 整包异常能更早终止，但同源成功运行留下的余量小于已完成用例报告时长的增长，正常推进也可能被累计预算截断。

**把 SQLite 拆为单独串行调用。** 可能减少竞争，但现有数据没有证明需要改变执行拓扑，也没有证明这能消除原因。有持续竞争证据时可以另行比较，当前不改变包划分或并发方式。

## 后果

所有等待仍有界；代价是整包 watchdog 最晚可比原设置晚五分钟触发，作业级终止可晚十分钟。包的累计执行预算不能用来解释某个行为超出自身 deadline，也不能将一次未完成的运行算作通过。

十分钟内仍无法完成、某个固定用例持续停滞，或同源比较出现可重复的局部回归，都需要重新定位执行进展与原因；本决定的累计耗时证据不能成为继续提高上限的依据。保留 skip、无测试、缺失 verdict 与进程失败的拒绝，才能让新增预算只提供执行余量。
